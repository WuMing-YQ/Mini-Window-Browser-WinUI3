# 小窗浏览器：WinUI 3 完整界面重构设计 01

日期：2026-10-09。状态：界面布局已获用户认可；2026-10-09 用户确认“别的都设计的挺好”。书签快捷列表按反馈补齐。下文技术拆分作为实施依据，具体任务见配套实施计划。

预览入口：`docs/design/winui-redesign-preview.html`。它是本地交互设计稿，不是 Windows 应用，也不加载真实网页、注册系统热键或操作系统窗口。示例书签、预设及视频画面均为演示数据；修改只存在于本次页面内存，刷新后恢复。

## 1. 目标与已确认范围

为 Windows 小窗浏览器完整重做界面，使它在玩游戏时看网页、视频更方便。所有现有界面纳入迁移，保留现有底层能力、用户数据与熟悉的操作。

用户已明确：

- 采用 WinUI 3 方向；整体界面重构，包括主窗口、标签、地址栏、书签、预设、设置、菜单、提示和关于。
- 两种沉浸：鼠标挖孔、移入减淡；减淡比例 R 表示相对于基础不透明度 B 再降低多少，最终为 B × (1 − R/100)。不新增第三种常驻模式；R=0 即持续按基础不透明度显示。
- 沉浸中可动态调整当前不透明度，不要求退出沉浸。
- 普通且小窗拥有焦点时，组合键＋滚轮快速调整窗口大小。网页有焦点也算；沉浸、游戏后台、最大化、隐藏及管理窗口输入时不触发。
- 取消固定 1080P 渲染再缩小、自动适宽网页等新增功能；迁移已有固定网页缩放能力。
- 当前阶段先完成设计；不继续游戏兼容性检查。

本稿提出的默认选择（设计建议，供本次审阅）：C++/WinRT 正式工程、紧凑 Fluent 风格、主题跟随系统、Ctrl+Alt+滚轮、每格约 5%、独立管理窗口、非模态沉浸面板。预览默认深色并展示浅色切换，不代表已选定正式主题默认值。

此前 Flutter 规格仅保留历史依据；本稿的技术路线、面板行为和阶段划分替代旧稿。已经取消的功能不重新引入。

## 2. 依据与实测边界

依据 `src/AppModel.h`、`src/Application.*`、`src/WindowModeController.*`、`src/ConfigStore.*`、`用户手册.md` 与办公室 WinUI demo 人工反馈梳理。

办公室环境：VS Community 2026 18.10、MSVC v145、Windows SDK 10.0.26100.0；C++ WinUI 开发工具和相关平台工具已确认安装。原 C++ Release 构建成功，118 项核心测试通过；C# WinUI demo 构建成功，0 警告、0 错误。这些是已有工程证据，不等于新 C++ WinUI 工程已构建。

用户反馈：demo 不透明度、挖孔、点击穿透、滚轮调整尺寸可用；恢复普通模式后标题栏与窗口按钮颜色不一致。游戏全屏尚未验证。正式迁移需处理恢复时的主题与非客户区同步，不能把 demo 当成全面兼容证明。

## 3. 布局方案比较与选择

| 方向 | 优点 | 代价 |
|---|---|---|
| 紧凑主窗口＋独立管理窗口（本稿建议） | 小窗内容面积大；设置不挤占网页；沉浸中可单独操作面板 | 管理窗口需要统一状态、位置、焦点与关闭规则 |
| 主窗口内常驻侧栏 | 书签与参数始终可见 | 小尺寸窗口明显挤占网页；穿透与沉浸时难以独立操作 |
| 所有功能塞入浮出菜单 | 主窗口最简 | 预设编辑、书签编辑和大量设置需要多层跳转 |

采用第一种。书签、预设和设置共用一个管理窗口，用对应页面打开；沉浸快捷面板单独存在，默认关闭。主窗口不常驻侧栏，不新增主页仪表盘。

## 4. 界面清单与操作

### 4.1 浏览主窗口

两行结构：上行标签＋新增＋窗口按钮，下行导航／地址输入＋收藏＋书签／预设＋沉浸＋设置。新增后退、刷新入口使用已有 WebView2 导航能力；没有历史时后退禁用，加载时刷新变停止。应用置顶延续原有默认行为，不因框架迁移丢失。

地址输入保持原网址／Bing 搜索解析规则与选中体验。标签关闭行为保持：最后一个标签关闭后恢复一个主页标签；右键提供关闭当前／其他／全部。采用原有单活动网页视图与会话切换策略，不引入后台多 WebView 播放。

布局断点均为 DIP，依据可用宽度而非屏幕分辨率：

- ≥600：显示完整入口，操作无长文字堆积。
- 390–599：书签、预设、设置、收藏移入“更多”；沉浸图标仍可用。
- 260–389：只显示活动标签；标签列表可切换及新建，后退／刷新进入菜单。
- <260：极简布局；保留活动标签／标签菜单、窗口按钮、地址／前往、沉浸与更多。普通窗口保留旧版约 160×120 的下限；沉浸保留约 64×64 的下限。320×240 是推荐交互尺寸，不作为迁移后新增的硬限制。

预览宽度包括 820／560／360／240；网页画面是占位。正式版窗口变小只改变网页可用区域；不得据此实现已取消的固定视口适宽缩放。

底部轻量状态行只在空间足够时显示：窗口状态和窗口大小快捷键提示。不增加沉浸期间常驻覆盖文字。

### 4.2 沉浸面板

面板约 320 DIP 宽，非模态，使用正常不透明背景。显示当前普通／沉浸状态、两种模式切换、基础不透明度、模式参数、结果预览、进入／退出沉浸与恢复普通模式。

- 基础不透明度 B：0–100%，滑块＋数值输入；两种模式独立记住 B，以兼容旧有配置结构。
- 移入减淡 R：0–100%，滑块＋数值输入；同时显示“移出 80% → 移入 40%”一类结果。
- 鼠标挖孔：半径 0–4000 物理像素，兼容旧配置单位；UI 与布局按 DPI 缩放，半径数值不暗中改成 DIP。孔内 0%，孔外 B。半径 0 表示无孔。
- 改值立即作用于网页窗口且不刷新网页、不暂停媒体；模式切换不重建 WebView。
- 面板打开时浏览器保持原沉浸状态，并继续按照鼠标位置计算效果；面板自己的区域不算作鼠标移入浏览器。无“打开设置时临时停止减淡”的隐含状态。
- 关闭面板仅关闭控制，不退出沉浸；浏览器可以维持 R=0 的常驻不透明度状态。

预览的“模拟鼠标移入”仅用于演示，不是正式软件新增选项。预览显示基础 80%、减淡 50%、半径 90 的示例，正式默认值及旧数据迁移见下文。

普通模式总是不透明且可交互；主动隐藏与沉浸减淡独立。B=0 或 R=100 时仍可从控制面板、已配置沉浸快捷键和托盘恢复普通模式。只要沉浸／主动隐藏生效就必须保留托盘入口，即便“最小化到托盘”关闭；这个开关只控制最小化动作。

全局输入保护仍可暂停热键；托盘恢复不受输入保护影响。若热键注册失败，清楚显示冲突与当前可用恢复途径，不能显示成功状态。面板不注册 demo 的固定 F8 恢复键；正式版沿用用户配置。

### 4.3 书签

日常入口是主窗口书签按钮的浮出列表，不直接打开管理窗口。点击后显示收藏列表，单击条目在当前标签打开并收起列表；Esc／点外侧关闭，方向键选择、Enter打开。窄窗口从“更多 → 书签”进入同一列表。列表底部“管理书签…”才打开管理窗口的书签页。无书签时给出星标收藏提示与管理入口。设计稿顶部“书签管理”是切换评审画面的导航，不是正式应用常驻导航栏。

管理窗口内左侧列表、右侧标题／网址编辑。提供新增、保存、打开、删除；双击打开。空列表显示“暂无书签”和新增入口。标题／网址错误贴近输入框显示，保存失败保留草稿。

星标快速收藏／取消与列表同步。删除提供简短确认；不增加标签分组、云同步或导入导出。列表长时滚动，不挤压编辑区。

### 4.4 场景预设

左侧场景列表，右侧名称和概要：窗口位置尺寸、标签数量与当前页、沉浸方式、基础／移入结果。提供保存当前、应用、重命名和删除。

实际保存范围完整沿用 `Preset` 并新增减淡比例及窗口滚轮设置：位置／最大化、标签会话、沉浸、吸附、热键、输入保护、隐藏与媒体行为、主页、网页缩放及全屏比例。主题和渲染模式保持全局，书签不属于预设。

应用前简短确认会替换当前标签和窗口设置，避免用户丢失页面输入。应用返回普通模式并恢复保存的普通／最大化几何，不自动进入穿透。校验去除首尾空格后名称非空且不重名；删除只删除所选预设。未保存的书签／预设编辑草稿，切换条目或关闭窗口时提示放弃或继续编辑。

### 4.5 设置

采用六类导航，不再把所有参数放在一条长表单：

| 类别 | 原有选项／新增选项 |
|---|---|
| 窗口与行为 | 最小化到托盘、边缘吸附距离、最大化顶部拖动、组合键＋滚轮调整尺寸 |
| 沉浸 | 模式、两种模式的基础不透明度、减淡比例、挖孔半径、打开独立控制、恢复入口 |
| 网页与媒体 | 主页、固定网页缩放开关与25–500%数值、视频全屏自动按比例调窗、锁定比例、隐藏自动暂停、隐藏允许媒体键、长按快进2–5倍 |
| 快捷键 | 原有7项动作的键位与启用状态、输入保护、窗口滚轮组合键；冲突状态与捕获反馈 |
| 外观 | 跟随系统／深色／浅色；所有窗口与标题栏同步 |
| 诊断与关于 | GPU／软件兼容选择、重启提示、复制诊断、恢复默认、版本、上游署名／链接与许可证 |

一般设置即时应用，数值离开输入框校验并落盘；拖动过程中及时作用窗口，保存节流。非法值不静默存入；失败时显示错误并保留用户输入。依赖项禁用但保留值：固定缩放关闭时比例禁用；自动按比例调窗关闭时锁定比例禁用。渲染模式下次启动生效，不自动重启。

恢复默认只恢复窗口和功能设置，保留书签／标签；使用确认框。复制诊断需要真实数据；设计稿只演示位置，不伪造检测值。

### 4.6 菜单、提示与恢复

主窗口“更多”承接窄布局入口；标签菜单保留原有关闭动作。托盘至少含显示小窗、恢复普通模式、沉浸控制、设置、退出。所有这些界面均以新视觉呈现；托盘菜单可用系统原生样式，保证输入与可访问性。

WebView 初始化中、导航失败、浏览器进程异常分别显示可恢复状态；失败页提供重试与打开设置。浏览器进程异常后先恢复可操作窗口，再处理重建，不无限自动重启。退出时按原规则保存配置与会话；写入失败不能宣称保存成功。

## 5. 视觉与可访问性

WinUI 3 是实际界面开发框架，Fluent 是视觉设计体系；本稿的“紧凑 Fluent”表示控件风格，不是改用另一个框架。

紧凑 Fluent：Windows 系统字体、统一线性图标、轻量分隔、约 4–8 DIP 控件圆角、少量绿色强调。主窗口不加大块装饰性标题或持续状态横幅。绿色为本稿建议，正式可在评审后调整。

正式 WinUI 使用语义主题资源与系统主题响应。深浅色都要涵盖地址栏、管理窗口、焦点、选中、错误、工具提示、标题栏和最小化／最大化／关闭按钮。修复 demo 的恢复后标题栏颜色不一致，不能仅修文字颜色。

控件为原生 WinUI 控件；键盘可达、图标有辅助功能名称、滑块读出数值与单位；对话框管理焦点并支持 Esc。常规文字不小于 12 DIP；主要输入与菜单14 DIP。触控目标适当扩大；减少动态效果时关闭非必要过渡。

不透明度变化以用户拖动直接响应为主，不加入持续动画。沉浸模式不显示应用工具栏、状态行或控制面板，除非用户主动打开独立面板。

## 6. 架构与原生复用

建议正式实现 C++20＋C++/WinRT＋WinUI 3＋WebView2。C# demo 保持技术参考，不继续堆业务代码。所有应用 UI 由 WinUI 绘制，网页仍由一个活动 WebView2 内容宿主负责；不使用第二个 WebView 绘制界面。

| 边界 | 职责 | 可复用依据 |
|---|---|---|
| WinUI Shell | 主窗口、管理窗口、快捷面板、表单及可访问性 | 替代旧 Direct2D UI、Win32表单 |
| App Coordinator | 用户命令、状态发布、错误反馈、窗口生命周期 | 从 `Application` 按需抽出协调职责 |
| BrowserHost | WebView2生命周期、导航、标签会话、网页缩放、媒体接口 | `Application`浏览器部分、`MediaBridge`、`WebViewZoom` |
| Window Service | HWND样式、置顶、几何、沉浸、全屏和恢复 | `WindowModeController`；适配WinUI窗口宿主 |
| Input Service | 全局热键、输入保护、焦点内滚轮、长按恢复 | `HotkeyManager`、`InputGuard` |
| Settings Store | 配置、预设、书签、迁移与原子保存 | `ConfigStore`、`AppModel` |

数据流：用户命令 → Coordinator → 所属原生服务 → 实际状态快照 → 各 WinUI 窗口更新。OS实际状态是权威来源；UI 不先把失败操作显示成成功。UI线程承载窗口、WebView及WinUI更新；跨线程输入保护继续用有效期标识丢弃过期结果，关闭后回调不得复活窗口。

主窗口包含 WinUI 控件与网页内容；沉浸时隐藏应用控件并让网页填满小窗。控制面板是独立 HWND，不承受浏览器的透明、挖孔与穿透。管理窗口也不随浏览器减淡。窗口服务统一管理进入、退出、失败恢复时的样式、布局、几何、主题刷新和置顶。

WinUI内容层级、窗口合成与实际全屏覆盖仍有风险；当前用户不要求继续兼容性测试。设计不指定未经新工程验证的截帧、纹理复制或跨进程方案，不把C# demo的结果推广为最终C++宿主已验证。

## 7. 滚轮调窗规则

建议默认 Ctrl+Alt+滚轮，可在设置选择修饰键组合；每标准刻度乘1.05或除1.05，保留窗口外框当前长宽比。固定左上角，尺寸受最小值和当前显示器工作区约束；必要时平移确保可见。高精度滚轮累计余量。

仅普通、非最大化、非沉浸、非隐藏且主窗口／内嵌网页有焦点时拦截；设置／快捷面板焦点不触发。捕获后不再传递给网页产生滚动或网页缩放；无组合键则保持网页行为。手动改窗不改变网页固定缩放。此操作可在连续滚轮事件中直接更新尺寸，不增加动画、后台控制或“实时跟随”机制。

## 8. 数据兼容与迁移

原 `config.ini`、标签会话、书签、预设及 WebView 网站数据均需保留。正式重构使用有版本的配置，迁移前备份旧配置，解析和校验全部成功后原子写入新配置。失败时不覆盖源文件。新旧测试版使用独立输出和配置目录，迁移不得在用户不知情下覆盖正在使用的旧程序数据。

旧整体透明模式的B保留，R默认100，保持原移入完全隐藏的含义；旧挖孔孔外实际100%，迁移有效B为100%。两种模式的B、R和每个预设独立迁移。半径继续使用物理像素，不在200% DPI下悄悄翻倍。首次全新配置建议沿用旧默认模式、B=100、R=100、半径400px；预览中的80/50/90仅为效果示例。

网站数据可复用既有用户数据位置，前提是生命周期与访问权限允许；不能把站点数据当作源码同步。禁止把浏览历史、Cookies、办公室连接密码写入仓库、预览或日志示例。

## 9. 分阶段实现顺序

这是交付顺序，不是已批准的详细执行计划：

1. 审阅本稿及交互预览，收敛布局、用词和默认操作；之后编写正式实施计划。
2. 建立正式C++ WinUI工程与可构建基线；接入WebView2、状态协调与原窗口服务。
3. 完成主窗口和普通／最大化／沉浸／隐藏／恢复闭环，修复标题栏恢复；保留故障恢复入口。
4. 迁移完整管理界面、原设置、标签、书签和预设及配置迁移。
5. 接入比例减淡、沉浸中实时调节和焦点内滚轮调窗。
